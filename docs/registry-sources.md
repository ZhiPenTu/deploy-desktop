# 镜像源管理

## 配置与使用

入口为“设置”的“镜像设置”板块，镜像源列表与清单拉取在同一页面维护。支持兼容 Docker Registry V2 的公开或私有仓库，如 ACR、Harbor、GHCR。

首次打开列表时预置 DaoCloud 加速（`docker.m.daocloud.io`）、毫秒镜像加速（`docker.1ms.run`）和轩辕镜像加速（`docker.xuanyuan.me`）三个国内公共加速源，命名空间预设为 `library`，对应 Docker Hub 官方镜像的路径前缀；拉取组织镜像（如 `bitnami/nginx`）时先清空命名空间。默认源与自行添加的源一致，可编辑或删除；全部删除后不会再次生成。

- 名称：本机唯一的镜像源名称。
- 仓库地址：主机名与可选端口，例如 `registry.example.com:5000`，不能包含账号、密码、路径或查询参数。支持粘贴 `https://` 地址并自动规范化。单段主机名需附端口，如 `harbor:5000`。
- 命名空间：可选的仓库路径前缀，如 `team/project`。
- 用户名：公开仓库可留空；私有仓库填写具有拉取权限的账号。
- 密码或令牌：可保存以便复用，也可留空，在每次拉取时输入。编辑时留空保留原密码；更换地址或用户名会清除旧密码，需重新填写；可以显式清除已保存密码。

“测试本机连接”始终从本机发起。有已保存凭据时使用临时 Docker 配置验证登录；无需登录时通过 HTTPS 请求仓库 `/v2/` 并检查 Registry V2 响应。公共加速仓库通常以带 Registry V2 响应头的 401 匿名挑战应答，视为可连接，公开镜像可直接拉取。测试通过只说明连通性或登录有效，不保证对具体镜像有访问权限，也不代表远程目标机可访问仓库。未保存密码的私有源请先保存密码后测试，或在实际拉取时输入本次密码。

仓库使用 HTTP 或自签名证书时，需由操作者在执行拉取的机器上配置 Docker 信任与 insecure registries，应用不会修改 Docker 服务配置，也不会跳过 TLS 校验。无凭据的连接测试仅支持 HTTPS；已配置凭据的测试遵循本机 Docker 的仓库配置。

## 拉取规则

单镜像拉取位于“镜像列表”的“拉取镜像”：

- 不选择镜像源：填写完整镜像引用，可临时填写用户名与密码。
- 选择镜像源：可填写仓库内相对路径，例如 `app@sha256:<digest>`。完整引用由仓库地址、可选命名空间和输入路径组成。
- 输入完整仓库地址时必须与所选镜像源一致，完整地址不会再次添加命名空间。不同仓库的引用会被拒绝。
- 所有拉取引用必须包含合法的 SHA-256 digest，拒绝仅 tag 的引用。

清单拉取位于“镜像仓库”：

- 选择源时替换清单 `spec.registry`；源中命名空间非空时替换 `spec.namespace`，否则沿用清单命名空间。
- 不修改清单文件，不修改镜像 digest 或平台。
- 切换镜像源、修改清单来源、编辑或删除当前源时使预览失效，必须重新加载并确认实际镜像地址。
- 本地拉取在本机 Docker 执行；远程拉取通过当前 SSH 连接在目标机执行。保存的凭据只发送给选定源对应的仓库。

## 存储与安全

Rust 命令集中在 `src-tauri/src/commands/registry_sources.rs`；前端仅通过 `src/api/tauri.js` 调用。

配置保存在应用配置目录（与 `profile.json` 同目录），运行时维护的镜像源与部署拓扑配置独立：

- `registry-sources.json`：名称、地址、命名空间、用户名与密码存在标记，不含密码原文。
- `registry-secrets.json`：按镜像源 ID 保存密码。Unix 上文件创建权限为 0600，通过同目录临时文件替换写入；不应复制到仓库或分享。

列表与保存命令不返回密码。删除源同时删除对应密码；更换地址或用户名不会继承旧凭据。单次登录使用权限为 0700 的临时 Docker 配置，本地在任务结束后清理，远程在每次拉取脚本退出时清理。密码通过标准输入传给 Docker，不出现在 Docker 命令参数中。连接及登录失败使用可操作的中文提示。

浏览器预览可展示界面，但保存、删除、测试和拉取操作明确返回不可用，不生成成功结果。前端交互模拟不能证明真实私有仓库或 SSH 链路有效。
